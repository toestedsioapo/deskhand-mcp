# M1 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buildable ESM + strict-TS package whose `deskhand-mcp` bin serves a `ping` tool over stdio, whose `deskhand` bin answers `--help`, with CI green on Node 24.15 and 26 across Windows and Linux.

**Architecture:** Two thin entry points (`src/server.ts`, `src/cli/index.ts`) over a shared `src/config/` stub. `ping` lives in `src/tools/ping.ts` (schema + handler) and is registered by `src/server.ts`. No ledger, providers, Tempo or approval code yet (M2+). Tests drive the built bins as child processes, so they also guard packaging.

**Tech Stack:** Node >=24.15, TypeScript strict (ESM, `NodeNext`), `@modelcontextprotocol/sdk` pinned exactly to `1.32.2` (stdio), Zod `^4.6.7`, Vitest `^5.1.0`, pnpm, `@modelcontextprotocol/inspector` pinned exactly to `1.0.4` (dev), GitHub Actions. Versions looked up on npm on 2026-11-09; the lockfile is committed.

**Version notes (checked 2026-11-09):**
- SDK `1.32.2` `McpServer.registerTool(name, { title?, description?, inputSchema?, outputSchema?, annotations? }, cb)` types `inputSchema` and `outputSchema` as a raw shape **or a full Zod schema** (`AnySchema`), and the SDK's `zod` peer range is `^3.25 || ^4.0`. So `pingInputSchema = z.object({}).strict()` is accepted as-is. Task 2's test still proves the extra-argument rejection at runtime.
- Inspector: the latest `2.x` requires Node `^24.22.1 || ...`, which would break `engine-strict` installs on our Node 24.15 floor. `1.0.4` requires Node `>=22.7.5` and exposes the `mcp-inspector` bin. Do not bump to 2.x until the floor allows it.
- Vitest `5.1.0` requires Node `^24.0.0` or newer, fine for the floor.

**Spec:** `docs/ROADMAP.md` (M1 row, including its listed additions), `docs/ARCHITECTURE.md` (Layout, Packaging), `docs/TEST_PLAN.md` (Startup, Matrix, Manual), `docs/adr/0004-sqlite-driver.md` (warning policy, Node floor). Contracts: `CLAUDE.md`.

## Global Constraints

- Node `engines.node` is exactly `">=24.15"`; `"type": "module"`; license MIT.
- Package name `@marvinliem/deskhand-mcp`; `bin`: `{ "deskhand-mcp": "dist/server.js", "deskhand": "dist/cli.js" }` (ARCHITECTURE.md Packaging).
- TypeScript `strict: true`; ESM only; no native modules.
- Tests run with Vitest; no live Google calls; no secrets committed; `.env*`, `credentials*.json`, `token*.json` gitignored.
- stdout of `deskhand-mcp` carries only MCP protocol frames; all logs go to stderr, and stderr must be empty on clean startup (ADR 0004; no warning filter on >=24.15).
- Never publish locally; no release workflow in M1.
- Commands: `pnpm install`, `pnpm build`, `pnpm test`, `pnpm inspect`, `pnpm dev`.
- Tests that run the built bins never build themselves: a Vitest `globalSetup` builds `dist/` once before any test file starts (no race between files).
- `ping` is a permanent tool (SPEC §4). In M1 it cannot write a ledger row; this gap is recorded in ROADMAP M1 and M2 closes it.

## Review Focus

- Server started with stdin closed immediately: exits 0 without stack trace or stderr noise.
- `ping` called with unexpected extra arguments: rejected by the Zod schema with an MCP error, server stays alive.
- `deskhand` with no args, `--help`, `-h`, and an unknown subcommand: help on the first three (exit 0), message to stderr and exit 2 on the last.
- Bin files run via a symlink or `npx` shim: the entry-point guard must not depend on `import.meta.url === argv[1]` string equality.
- Running on Node below 24.15 (dev machine is 24.11.1): clear "requires Node >=24.15" message rather than a cryptic failure.
