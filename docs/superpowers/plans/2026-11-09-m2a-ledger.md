# M2a Ledger and Logged Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A server whose every tool call (`ping`, `ledger_query`, `action_explain`, bad input, unknown tool) lands in a SQLite audit ledger whose schema, value sets and tool schemas are written down and snapshot-tested as contracts.

**Architecture:** `src/config/` resolves env and the data dir. `src/ledger/` owns SQLite (`node:sqlite` only in `db.ts`), forward-only migrations, canonical hash, redaction and event/action queries. Logging is done by a `LoggingTransport` that wraps the MCP transport, so it sees every `tools/call` request and its response, including SDK validation failures and unknown tools, and writes the `tool_call` row before the response leaves the process. It also counts in-flight requests, which M2b's shutdown fix uses. Plan store, apply engine, CLI approval and the fixture provider are M2b.

**Tech Stack:** Node >=24.15 `node:sqlite`, `@modelcontextprotocol/sdk` 1.32.2, Zod 4, Vitest 5. No new runtime dependencies (ULIDs are hand-written).

**Spec:** `docs/ROADMAP.md` (M2 row), `docs/SPEC.md` §4-5, `docs/ARCHITECTURE.md` (Ledger, Ledger vocabulary, Canonical JSON, Contract documents), `docs/adr/0003-ledger-format.md`, `0004-sqlite-driver.md`, `0005-shared-sqlite-location-and-concurrency.md`, `docs/SECURITY.md`, `docs/TEST_PLAN.md` (Ledger, Contracts, Config, Paths, Ledger version, Startup rows). Contracts: `CLAUDE.md`. Companion plan: `2026-11-09-m2b-approval.md`.

## Global Constraints

- Node `>=24.15`, ESM-only, TypeScript strict, MIT. No native modules. No new runtime dependency.
- Nothing outside `src/ledger/db.ts` imports `node:sqlite`. Pragmas: `journal_mode=WAL`, `busy_timeout` default 5000 ms, `foreign_keys=ON` (ADR 0004/0005).
- Schema version is `PRAGMA user_version` only; no `schema_version` table; migrations are forward-only modules in `src/ledger/migrations/` (ADR 0003).
- Three tables `actions`, `events`, `expenses`. `events` is append-only: triggers abort UPDATE and DELETE. Timestamps are `TEXT` ISO-8601 UTC with milliseconds and `Z`. JSON columns are `TEXT`.
- Every tool call writes exactly one `tool_call` event, failures and rejections included. Ledger previews never contain tokens, credentials or full email bodies.
- stdout of `deskhand-mcp` carries only MCP frames; stderr is empty on clean startup. The server fails closed: if config is invalid or the ledger cannot be opened, it exits 1 with one stderr line and runs no tools.
- Existing tool schemas (`ping`) must not change; snapshots stay byte-identical.
- No live Google calls. No secrets committed. `docs/tools.md` stays generated (M5), never hand-edited.
- Tests never touch the real user data dir: every test that opens a ledger or spawns a bin passes a fresh temp `DESKHAND_HOME`.
- Commit messages follow M1's style (`feat:`, `test:`, `docs:`); one commit per task.

## Review Focus

- `DESKHAND_HOME` unset on a machine with no data dir yet: dirs are created, server starts, stderr empty.
- `DESKHAND_PLAN_TTL_HOURS=0`, `169`, `abc`, `1.5`, empty string: startup config error naming the variable; never silently clamped.
- `DESKHAND_ALLOW_WRITES` set to `true`, `yes`, `0`, ` 1`: writes stay off. Only the exact string `1` enables them.
- A tool call with bad arguments, and a call to a tool that does not exist: one `tool_call` row each (`outcome=error`, `error_code=INVALID_INPUT` / `UNKNOWN_TOOL`), server stays alive.
- A tool argument or result containing something that looks like a token or a 5 000-character email body: the stored preview is redacted/truncated, never verbatim.
- Ledger file is corrupt, read-only, or its `user_version` is newer than this build: server exits 1 with a clear message rather than running unlogged.
- Two connections writing at once: the busy timeout is honoured and no event row is lost or duplicated.

### Task 1: Contract documents

Docs-first (ROADMAP M2). The decisions the architecture left to the plan are made here; the owner reviews them in this plan. Later tasks implement these documents and pin them with tests.

**Files:**
- Create: `docs/ledger-contract.md`, `docs/fixture-format.md`, `docs/tools-contract.md`
- Modify: `docs/ASSUMPTIONS.md` (close the action-id-format item and the fixture-shape item; link the three documents)

**Decisions to write down (exact values):**
- **ids:** `actions.id` and `expenses.id` are `TEXT`: `act_` + 26-char Crockford-base32 ULID (uppercase). Confirmation is the last 4 characters of the whole id (random part), compared case-insensitively after trimming. `events.id` is `INTEGER PRIMARY KEY AUTOINCREMENT` (ordering is the append order).
- **DDL** for `actions`, `events`, `expenses` with column types, nullability, `CHECK` constraints built from the value sets, `events.action_id` referencing `actions.id`, indexes (`events(action_id)`, `events(ts)`, `actions(status)`), and the two `events` triggers. `expenses.amount_minor` is an integer in the currency's minor unit; `currency` is an ISO-4217 code.
- **Value sets:** `status`, `outcome`, `approval_method` (`cli_tty`), `rejection_method` (`cli_tty | cli_no_tty`), `events.kind` (ARCHITECTURE list), `error_code` (ARCHITECTURE list plus `UNKNOWN_TOOL` and `NOT_PENDING`; `NOT_PENDING` is the approve/reject refusal for a plan whose status is `rejected`, `failed` or `applied`, while `ALREADY_APPROVED` is for `approved`).
- **Row sequences:** as ARCHITECTURE, with the rule that lifecycle rows (`plan_created`, `approved`, `approve_refused`, `rejected`, `applied`, `apply_refused`, `apply_failed`) are written first and the `tool_call` row last (it is written when the response is produced), and that a `tool_call` row carries `action_id` when the result names one. `outcome` mapping for `tool_call`: gate refusals (`WRITES_DISABLED`, `UNKNOWN_ACTION`, `PLAN_EXPIRED`, `NOT_APPROVED`) are `rejected`; every other error code is `error`.
- **`preview_json`:** `{"v":1,"input":<redacted>,"output":<redacted|null>,"note":<string|null>}`. Redaction: object keys matching `/token|secret|password|authorization|credential/i` become `"[redacted]"`; keys named `body`, `html`, `content` and any string over 200 chars are cut to 200 chars followed by `…[truncated sha256:<first 8 hex of the full string>]`; whole preview capped at 4 KB (excess fields replaced by `"[omitted]"`).
- **Status transition table, CLI error codes, apply gate order:** `WRITES_DISABLED`, then `UNKNOWN_ACTION`, then replay if `status=applied` (returns stored result, `tool_call` ok), then `NOT_APPROVED` (any status other than `approved`), then `PLAN_EXPIRED`, then hash check (`PLAN_MODIFIED`, status becomes `failed`), then re-check (`STALE_PLAN`, `failed`), then provider write (`PROVIDER_ERROR`, `failed`). Gate refusals leave status unchanged.
- **Ledger open failure** is a startup exit, not a tool error (fail closed).
- **`docs/fixture-format.md`:** `fixture_version: 1`, JSON only. Top level: `now` (ISO instant the fake clock starts at), `calendars: { [calendarId]: { events: [{id, title, start, end, attendees, etag}] } }`, optional `settings: { latency_ms?: number, write_log?: string }`. `write_log` is a file the fixture provider appends one JSON line to per provider write (this is how tests, Deskbench and the red-team harness observe writes from outside the process). Env: `DESKHAND_FIXTURE` (path; unset means an empty world).
- **`docs/tools-contract.md`:** schemas for `ping` (unchanged), `ledger_query`, `action_explain` (Tasks 6 and M2b), and the result convention (`structuredContent`; errors are `isError: true` with `{ error_code, message, action_id? }`).
