# Fixture world format (v1)

Status: written in M2a. The fixture world is the fake calendar/mail universe loaded by `src/providers/fixture`. It is a contract: tests, Deskbench scenarios and Deskflow demo seed data all use it. Changing the shape is breaking and bumps `fixture_version`.

## Loading

- JSON only. UTF-8, no comments.
- `DESKHAND_FIXTURE` is the path to the file. Unset means an empty world (no calendars, clock at the real current time).
- The loader rejects: a missing or non-`1` `fixture_version`, unknown top-level keys, unknown keys inside `settings`, duplicate event ids within a calendar. Extra keys are errors in v1 so that later additions (mail threads, per-person rule sets) force a `fixture_version` bump.

## Shape

```json
{
  "fixture_version": 1,
  "now": "2026-11-10T09:00:00.000Z",
  "calendars": {
    "primary": {
      "events": [
        {
          "id": "evt_standup",
          "title": "Team standup",
          "start": "2026-11-10T09:30:00.000Z",
          "end": "2026-11-10T09:45:00.000Z",
          "attendees": ["ana@example.com", "ben@example.com"],
          "etag": "e1"
        }
      ]
    }
  },
  "settings": {
    "latency_ms": 0,
    "write_log": "writes.jsonl"
  }
}
```

| Key | Type | Required | Meaning |
|---|---|---|---|
| `fixture_version` | number, must be `1` | yes | format version |
| `now` | ISO-8601 UTC instant | yes | where the fake clock starts. The fixture provider and the server's clock (when a fixture is loaded) read this; time does not advance unless a test advances it |
| `calendars` | object, calendar id to `{ events }` | yes (may be `{}`) | calendar ids are free strings; `primary` is the default |
| `calendars.<id>.events[]` | object | yes (may be `[]`) | `id` string unique per calendar; `title` string; `start` and `end` ISO-8601 UTC instants with `start < end`; `attendees` array of email strings (may be empty); `etag` non-empty string, opaque, changes when the event changes |
| `settings.latency_ms` | non-negative integer | no, default `0` | artificial delay added to every provider call (for timeout and concurrency tests) |
| `settings.write_log` | string path | no | file the fixture provider appends to on every provider write; relative paths resolve against the fixture file's directory. Absent means no log |

## Write log

`write_log` is how tests, Deskbench and the red-team harness observe writes from outside the process. For every provider write (and only writes; reads are not logged) the fixture provider appends exactly one line of JSON, flushed before the write is acknowledged:

```json
{"seq":1,"ts":"2026-11-10T09:00:00.000Z","op":"calendar.createEvent","idempotency_key":"<64 hex>","request":{}}
```

`seq` starts at 1 per process and per file append; `ts` is the fake clock; `op` is the provider method name; `idempotency_key` is the one derived from the action id (see `docs/ledger-contract.md`); `request` is the provider request body, redacted by the ledger preview rules. A fixture write with an idempotency key already present in the world is a no-op that returns the existing event (and writes no log line), which is how crash recovery is simulated.

## Determinism

The clock is fixed at `now`. Ids generated by the provider for new events are derived from the idempotency key, so replays produce identical results. The id seed for action ids is a test-constructor option, not part of the file format.
